# argocd-bootstrap tests

`check-projects.sh` is a static check of the app of apps. It needs no cluster: it renders the charts with Helm and checks the result against the AppProjects the same render produces.

```bash
argocd-bootstrap/tests/check-projects.sh                 # every clusters/*/cluster.yaml
argocd-bootstrap/tests/check-projects.sh lab             # one cluster definition
argocd-bootstrap/tests/check-projects.sh --deep lab      # also render the charts the Applications deploy
```

Requirements: `helm`, `yq` (mikefarah v4) and `jq`. The script prints one error line per violation and exits 1 when there is any. `LOG_LEVEL=debug` shows every Helm command of the deep pass.

## What it renders

For each cluster, `helm template root argocd-bootstrap -f clusters/<name>/cluster.yaml` in three variants:

| Variant | Extra values |
|---|---|
| `configured` | none |
| `applicationset` | `applicationSet.enabled=true` |
| `all-toolchains` | `toolchains.<name>.enabled=true` for every switch found in `templates/` (`dig "<name>" "enabled"`, and `.Values.toolchains.<name>.enabled` in templates that predate the `dig` form) |

The root Application rendered by `bootstrap/` is checked with every variant, except for a remote cluster in hub mode, whose root belongs to the hub. Applications generated by an ApplicationSet list generator are expanded (`{{ .key }}` placeholders of the elements) and checked like static ones. Other generators, such as the Git generator of `tenants`, are not expanded; the script warns about them.

## Checks

1. Application, ApplicationSet and AppProject names are unique per kind; Application names are DNS labels of at most 63 characters.
2. No Application uses the `default` project (an empty `spec.project` counts as `default`); every project is rendered in the same output.
3. The destination of every Application is permitted by its project, with Argo CD's matching: `server` or `name`, namespace globs, `!` deny entries.
4. Every `argocd.argoproj.io/manifest-generate-paths` entry exists. Entries starting with `/` are relative to the repository root; other entries are relative to the source path, and are an error in a multi-source Application. Entries with `{{` are skipped.
5. Every source `path` in this repository exists, and every value file exists unless the source sets `ignoreMissingValueFiles`. `$<ref>/` value files resolve against the source that declares `ref: <ref>`.
6. `--deep`: every Helm chart of this repository that an Application deploys is copied to a temporary directory, its missing dependencies are built (with private Helm configuration and cache), and it is rendered as Argo CD renders it: release name, destination namespace, `--kube-version <cluster.kubernetesMinor>.0`, `--include-crds` unless `skipCrds`, the value files that exist, `valuesObject` or `values`, and `parameters`. Each object is then checked against the Application's project: cluster-scoped kinds against `clusterResourceWhitelist` and `clusterResourceBlacklist`; namespaced objects (namespace from the object, else the destination) against `destinations`, `namespaceResourceBlacklist` and, when set, `namespaceResourceWhitelist`. Applications whose project is `default` or not rendered are rendered but not checked; check 2 already reports them.

An object is cluster-scoped when its kind is a built-in cluster-scoped Kubernetes kind, when a CRD with `scope: Cluster` for it is rendered anywhere in the same deep pass, or when it is in the script's table of well-known add-on kinds (`ClusterIssuer`, `ClusterPolicy`, `GatewayClass` and others). Any other kind is treated as namespaced; for a kind outside the Kubernetes API groups without a CRD in the pass, the script warns.

## Limits

- A cluster-scoped kind whose CRD is installed by another route (not rendered by any chart in the pass) and that is not in the table is treated as namespaced, so a missing whitelist entry for it goes unnoticed. The warning names such kinds; add them to the table.
- The deep render has no live cluster: `.Capabilities.APIVersions` holds only built-in APIs (plus `helm.apiVersions`), `lookup` returns nothing, and `helm.fileParameters` are not applied. Charts that branch on these can differ from what Argo CD renders.
- Directory and Kustomize sources are not rendered in the deep pass.
- A cluster name in a destination is not resolved to its server URL; `server` and `name` are compared as written.

## CI

CI runs the check in the `argocd-bootstrap` job.
