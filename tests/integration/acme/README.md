# ACME integration test

Issues the platform gateway certificate (`platform-tls`) from a local ACME server in a kind cluster, with the charts and the Argo CD Application values of this repository. It replaces a Let's Encrypt run as far as a laptop allows.

```bash
tests/integration/acme/run.sh            # HTTP-01
tests/integration/acme/run.sh --dns01    # HTTP-01, then DNS-01 through RFC2136
```

`--keep` (or `ACME_KEEP=1`) leaves the cluster running for inspection; otherwise it is deleted on exit, also on failure. An existing cluster with the same name is replaced, so the script can be rerun. Evidence is written to `_out/integration/acme/`: the cluster definitions used, the Challenges and solver HTTPRoutes recorded while they existed, the Pebble and BIND logs, the Pebble root, the certificate each host served, the final Certificate, and diagnostics on failure.

Requirements: docker, kind, kubectl, helm, yq v4, jq, openssl, and uvx (or check-jsonschema) for `hack/validate-config.sh`; network access to the chart and image registries; about 2.5 GB of free Docker memory (`ACME_MIN_FREE_MIB`). Other settings: `ACME_CLUSTER` (default `it-acme`) and `ACME_TIMEOUT` (seconds per wait, default 300).

Last result (2026-11-16, Pebble 2.10.3, BIND 9.20, Kubernetes v1.36.4, run with `--dns01`): passed. HTTP-01 issuance of `platform-tls` for the four host names, the computed renewal time and a forced renewal with a new private key, and DNS-01 issuance of the wildcard certificate through RFC2136.

## Setup

| Part | What the test uses |
|---|---|
| Cluster | kind, one node, `kindest/node:v1.36.4` (the lab `kubernetesMinor`) |
| ACME server | Pebble 2.10.3 in namespace `pebble`, `-strict`, validation on ports 80 and 443, 90-day certificates, no authorization reuse, no validation delay |
| ACME server TLS | Certificate from a throwaway test CA generated by the script; the CA is passed as `platform.acme.caBundle` |
| DNS | pebble-challtestsrv 2.10.3 serves the cluster domain (`localtest.me` from the lab file); CoreDNS forwards that zone to it without caching, so cert-manager and Pebble resolve the gateway host names alike. The DNS-01 phase replaces it with BIND 9.20 (`ubuntu/bind9`, multi-arch; the ISC image is amd64 only) holding the zone and a TSIG key that may only update TXT records |
| Platform | `gateway-api`, `cert-manager`, `envoy-gateway`, `misc` and `platform-gateway`, installed with helm in sync-wave order from the Applications that `argocd-bootstrap` renders for the test cluster definition: same chart path, value files and `valuesObject` |
| Cluster definition | `clusters/lab/cluster.yaml` with `platform.issuer: letsencrypt-staging`, `platform.acme.server` and `platform.acme.caBundle` set to Pebble, `platform.gateway.hostnames` set to the names `hack/validate-config.sh` requires for http01 (`argocd.localtest.me` and `hello-api.<env>.localtest.me` for dev, stage and prod), and the `letsencrypt` issuer switched off through `toolchains.misc.values`; checked with `hack/validate-config.sh` |
| Client | `curlimages/curl` 8.23.0 pod inside the cluster, connecting to the Envoy Service address and to the lab https node port on the node address |

`platform.acme.server` and `platform.acme.caBundle` are test-only keys. They default to empty, only redirect the `letsencrypt-staging` ClusterIssuer, and never change `letsencrypt`.

## What a pass proves

HTTP-01 phase:

1. The `letsencrypt-staging` ClusterIssuer from the misc chart registers an ACME account with an RFC 8555 server, over TLS verified with `caBundle`. The keys travel from the cluster definition through the misc Application into the ClusterIssuer.
2. cert-manager solves HTTP-01 through the `gatewayHTTPRoute` solver: each solver HTTPRoute attaches only to Gateway `platform`, listener `http`, in the gateway namespace (allowed by `httpAllowedRoutes: Same`), and takes precedence over the HTTPS redirect route on the same listener. Pebble fetches the token from each host name on port 80 through Envoy.
3. `platform-tls` becomes Ready for exactly `platform.gateway.hostnames`. The https listener serves it for each name, and the chain verifies against the Pebble root alone. The served leaf is the one in the Secret.
4. Renewal settings: `renewalTime` is `notAfter` minus `renewBefore` (720 h) for a 90-day certificate, the same arithmetic as for Let's Encrypt. A forced renewal (the `Issuing` condition that `cmctl renew` sets) validates the names again, rotates the private key (`rotationPolicy: Always`), and Envoy serves the new certificate without a restart.
5. Plain HTTP on the gateway still answers with a 301 redirect to https.
6. The proxy Service exposes the fixed node ports of `values-lab.yaml` (http 30080, https 30443) already while `platform-tls` is pending, which is when the https listener has no certificate, and the https node port serves the issued certificate. kind maps host ports 80 and 443 to these node ports in the lab demo.

DNS-01 phase (`--dns01`):

1. `platform.acme.dns01: {provider: rfc2136, config, credentialsSecretRef}` is rendered by misc as a valid `rfc2136` solver with `tsigSecretSecretRef`. cert-manager writes the TXT records with TSIG, passes its propagation check against the authoritative server, Pebble validates them, and the wildcard certificate (`<domain>`, `*.<domain>`, `*.<env>.<domain>`) is served for names under each level.

## What only a real Let's Encrypt run can prove

- Reachability from the internet: public DNS records for the host names, port 80 open through the load balancer, firewall and NAT, and Let's Encrypt's validation from several network locations. Here the ACME server sits inside the cluster.
- Let's Encrypt policy: CAA records (Pebble does not check them), rate limits, blocked or public-suffix names, and rejection of placeholder contact addresses such as `example.com` (`platform.certManagerEmail` must be real).
- The real directory URLs and their public TLS trust. The test replaces both with `server` and `caBundle`.
- A real DNS provider: API credentials and permissions (Cloudflare, Route 53 and the others), zone delegation, and propagation to public resolvers. BIND here is a single primary on the cluster network.
- Client trust: browsers trust Let's Encrypt production certificates, not staging ones; the test only trusts the Pebble root it fetched.
- Renewal in real time (about 30 days before expiry, with Let's Encrypt validity and ARI). The test checks the computed renewal time and forces one renewal.
- Argo CD behaviour: sync waves, `SkipDryRunOnMissingResource` and self-heal. The harness installs the same charts and values with helm in wave order; the GitOps path is covered by the e2e and reference harnesses.
- NetworkPolicies and Kyverno policies around the solver: neither is installed, and kindnet does not enforce NetworkPolicies. On an enforcing CNI, the solver pod in the gateway namespace is reached by the Envoy proxy through `allow-same-namespace` of the network-policies chart.
